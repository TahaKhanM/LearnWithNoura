# Phase 2 handoff — the lesson compiler (2026-08-26)

Phase 2 of the approved overhaul moves lesson authorship out of the realtime
voice session. A strong reasoning model now authors a complete,
geometry-validated lesson at session creation; the realtime model
(`gpt-realtime-2.1`, unchanged) executes it stage by stage. This document
records what was built, what is proven offline, what still needs an
authorized live run, and what was deliberately deferred.

## What changed

### Compiled-lesson contract (`shared/compiledLesson.ts`)

A `CompiledLesson` is the versioned, zod-validated product of compilation:
the original goal, the normalized objective, the full `LessonBlueprint`
(existing `shared/pedagogy.ts` schema, extended additively with structured
stages, per-stage checks with exact `questionOrTask` wording /
`responseMode` / target object IDs, and misconception branches), and — for
board-led lessons only — an anchor scene: validated add-only BoardOps plus
an ordered storyboard whose steps each carry a 1–2 sentence narration beat
and the object IDs they reveal. Schema-level cross-checks enforce that
board-led lessons carry an anchor, that storyboard steps cover every object
the ops add, and that conversation-led lessons carry no forced visuals.

The repository stores one `CompiledLessonRecord` per session
(`pending | ready | failed`, with a failure reason) in the additive
`compiled_lessons` table — SQLite (`server/store/db.ts` migration) and
Postgres (`server/store/migrations/003_compiled_lessons.sql`) — with
portable export/import parity in `server/store/portable.ts`.

### Compiler pipeline (`server/lesson/`)

`compiler.ts` drives the pipeline over the existing Chat Completions path
(no new provider dependency; model `NOURA_COMPILER_MODEL`, default
`gpt-5.6-terra`; reasoning effort `NOURA_COMPILER_REASONING_EFFORT`,
default `medium`):

1. **Normalization** — the parent's free-text goal becomes one concrete
   teachable objective, or 2–3 candidate objectives when the goal is vague.
2. **Authorship** — one structured-output call produces the blueprint and,
   for board-led lessons, a semantic-template-based anchor plan; the
   template's deterministic reveal checkpoints then receive model-authored
   narration beats.
3. **Headless validation** — every compiled scene runs through the REAL
   client pipeline (`compileScene`, inspection, annotation layout, quality
   budget) with DOM-measured KaTeX bounds: `headlessSceneValidator.ts`
   drives the existing `BoardHarness` dev page in headless Chromium via the
   `window.nouraPreflightScene` hook, and `src/board/domKatexMeasurer.ts`
   registers real KaTeX DOM measurement. A pure-Node approximation is never
   trusted; a missing harness URL fails closed.
4. **Self-correction and fallback** — rejection reasons feed back to the
   model for up to 2 retries; persistent failure retries the template with
   default parameters, then strips the lesson to conversation-led mode. An
   invalid lesson is never stored ready.
5. **Persistence and consumption** — `compilationService.ts` writes the
   pending record inside the session-creation request and compiles in the
   background; the lesson page polls the record's status.

`fixtureCompiler.ts` is the deterministic offline compiler (selected by
`app.ts` when no provider key exists, or forced by
`NOURA_LESSON_COMPILER=fixture`, which production startup refuses). Its
three checked-in fixtures — triangle angle sum (maths, board-led), water
cycle (non-maths, board-led via the cycle grammar), being brave
(conversation-led) — were generated by
`scripts/generate-lesson-fixtures.mts` from the real semantic templates.

### Realtime session: consume, never author

`create_lesson_blueprint` is gone from `server/realtime/tools.ts` and
`toolHandling.ts`; legacy `blueprint` event parsing remains only for
replaying old stored sessions. The proxy and the WebRTC call bootstrap
load the compiled record at connection time, refuse pending/failed records
(legacy sessions without a record still work), and seed lesson state with
the stored blueprint; `sessionRestore.ts` restores it with progress on
reconnect exactly as before. `server/realtime/instructions.ts` injects a
per-stage execution brief — the current stage's objective, its exact check
questions, and (for the anchor stage) the storyboard beats — refreshed on
every stage advance. The `establish` visual action resolves to the
pre-validated anchor scene when one exists: the model's semantic plan is
answered with the compiled ops and storyboard, so the voice model never
invents anchor geometry. `server/prompts/realtime.md` was rewritten to
execution-only duties and `promptConsistency.test.ts` pins the prompt to
the live tool surface and shared validator vocabulary.

### Bounded mid-lesson replanning

When evidence classification records a `missing_prerequisite` detour (a
deterministic server-side decision, not a model whim),
`server/realtime/detourPlanning.ts` schedules a compiler-authored detour
mini-plan (1–2 stages) asynchronously while the tutor bridges verbally.
The plan lands as an embedded `plan` on the existing `detourStack` entry
(additive `DetourPlanSchema` in `shared/pedagogy.ts`); `currentStage`
resolves to the active detour stage, the orchestrator's `ASSESSED` event
advances multi-stage plans, and the pop returns to the recorded stage. A
timeout (or compiler failure) falls back to the pre-existing simple detour
behavior unchanged.

### Session-creation API and UI

`POST /api/sessions` normalizes the goal in-request: a concrete goal
creates the session and starts compilation (201 with a `compilation`
status view); a vague goal returns candidates without creating a session,
and the parent's pick is confirmed via the same endpoint with `objective`.
`GET /api/sessions/:id` and `/continue` carry the compilation view;
continue re-keys a ready compiled lesson instead of recompiling. The home
page renders the candidate picker; the lesson page polls the record, shows
an honest "Preparing your lesson" state (Begin disabled) while pending, a
terminal error state on failure, and starts only on a ready record.

## Proven offline

- Compiler unit tests with a scripted chat double: valid-first-try,
  invalid-then-corrected, and persistently-invalid-→-fallback paths
  (`server/lesson/compiler.test.ts`).
- Headless validation through the real pipeline with DOM KaTeX bounds for
  all three subject fixtures, plus rejection of an over-budget scene
  (`tests/e2e/compiled-scenes.spec.ts`).
- Storage parity: `compiled_lessons` upsert/read on SQLite and Postgres,
  portable snapshot round-trip (`npm run test:storage`).
- API flows: direct goal, candidate selection, normalization failure,
  compilation-failure surfacing, and continue re-keying
  (`server/api.sessions.test.ts`).
- Realtime consumption: proxy refuses non-ready records, seeds compiled
  blueprints, resolves establish to the compiled anchor, injects stage
  context, and executes planned detours with timeout fallback
  (`server/realtime/proxy.test.ts`, orchestrator tests).
- Prompt/tool consistency and all fourteen completion gates at final HEAD.

## Requires authorized live verification

- **Real compiler output quality.** All model interactions in tests are
  scripted doubles; no live provider call was made. Whether
  `gpt-5.6-terra` at medium effort reliably authors good blueprints,
  templates, and narration needs an authorized live run.
- **Background compilation on Vercel.** Compilation runs `void`-async
  after the session-creation response. On serverless, work after the
  response is not guaranteed to complete; the deployed platform needs
  verification (e.g. `waitUntil` semantics) or a queued execution model.
- **Headless Chromium in the deployed compiler path.** Validation needs a
  reachable board-harness page and a launchable browser
  (`NOURA_BOARD_HARNESS_URL`); the deployed topology for this is
  unverified. Without it the compiler fails closed to conversation-led.
- **Live replan latency.** The detour-plan timeout default needs tuning
  against real model latency.

## Deferred

- Parent-facing preview/regeneration of the compiled lesson before
  handing the device over.
- Compiled-lesson reuse across sessions beyond continue's re-keying (no
  cross-goal lesson library or caching).
- Multi-anchor lessons (one anchor scene per lesson remains the rule) and
  storyboard beats for post-anchor stages.
- Migrating old stored sessions' live-authored blueprints into
  `compiled_lessons`; legacy replay parses stored events instead.
